# Design

## Consumer-shaped journey

A frozen descriptor captures fixed public verification material, a DIDComm
service endpoint, pairwise `from`/`to` values, a DID URL, and injected resolver
responses. It is derived from the donor dispositions rather than donor classes
or lifecycle code. The journey creates and locally resolves the selected peer
DID, parses its document and URL values, resolves and dereferences through
injected effects, and carries only the resulting identifiers through a
request-shaped boundary.

## Provider-neutral execution

One async assertion function accepts a provider factory, query-provider
factory, expected profile, and target identity. The legacy fixture implements
the same capability-named interfaces from fixed reviewed values; the Rust
route uses the target package entry. Shared assertions compare applicable
serialized values, document identities, relationships, service projection,
resolution correlation, and stable failure categories. Numalgo 4 remains a
Rust-only addition and is asserted as an explicit deviation rather than fake
legacy parity.

## Selection and rollback

Each target first selects the Rust route before generated initialization and
runs the journey. It then selects the injected legacy route in a fresh
selection boundary and reruns the same body. A deliberate Rust rejection is
terminal and increments no legacy call counter. No catch handler or automatic
fallback exists.

## Target and receipt model

Node ESM/CommonJS, real browser, React SSR, and hydrated React client invoke
the same assertion module. The receipt generator requires exact repository and
donor revisions, hashes the journey and assertion source, records assertion
counts per provider/target, and fails on missing, skipped, focused, quarantined,
or duplicate cases. React Native remains structurally not applicable.

## Evidence labels

The parity matrix may close the repository-local `consumer-proof` and
`rollback` gaps for applicable WASM targets, but continues to report partial
capabilities while external activation, support, budgets, publication, default
switching, and React Native remain open.

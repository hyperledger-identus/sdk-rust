## MODIFIED Requirements

### Requirement: The assurance claim remains first-party and evidence-bounded

The unsafe-code prohibition SHALL apply to authored first-party SDK source and
direct syntax generated by a first-party procedural-macro template whose
generated tokens carry a caller-origin span. Every direct implementation
template in `identus-derive` SHALL use the derived type identifier's span;
interpolated caller tokens SHALL retain their existing spans. A stable,
dependency-free, offline compile-fail fixture SHALL prove on exact Rust 1.98.1
that caller-spanned unsafe expansion syntax is rejected specifically by the
inherited unsafe-code forbid.

The prohibition SHALL NOT be represented as linting external dependency
internals, uniformly rejecting external or nested procedural-macro output,
proving logical or side-channel safety, or exercising unsupported
feature/target combinations. Dependency unsafe/native code SHALL continue to
be evaluated in dependency research and integration ADRs. External, nested or
otherwise ungoverned expansion spans for which rustc allows internal unsafe
SHALL remain an explicit indexed limitation.

#### Scenario: First-party direct template emits unsafe syntax

- **WHEN** a direct `identus-derive` implementation template emits an unsafe
  construct with the derived type's caller-origin span
- **THEN** the consuming opted-in SDK crate fails under the inherited
  `-F unsafe-code` policy

#### Scenario: First-party template behavior remains compatible

- **WHEN** supported string, byte and numeric `Newtype` shapes are expanded
- **THEN** existing runtime and trybuild suites pass without a public API,
  wire, runtime, dependency, feature, target or MSRV change

#### Scenario: External or nested macro output uses an allowed expansion span

- **WHEN** external or nested procedural-macro output carries a span for which
  rustc intentionally allows internal unsafe
- **THEN** the SDK does not claim the workspace forbid catches it and retains
  `SDK-LIM-008` plus dependency/macro review for that residual boundary

#### Scenario: Adopted dependency contains reviewed unsafe code

- **WHEN** Cargo compiles an external dependency under dependency cap-lints
- **THEN** the first-party gate does not claim to reject that source, and its
  unsafe/native posture remains explicit dependency-decision evidence

## Why

`#[derive(Newtype)]` lets invalid values into grammar-bearing newtypes (`DidMethod`, `Url`, `Version`) through three bypasses: the infallible `new`, the quiet `From<Inner>` impls, and the generated `Deserialize` that constructs `Self(inner)` with no validation. The serde path is the most dangerous — it is the untrusted input boundary (network, files, configs), and today an attacker-controlled string deserializes straight into an invalid `DidMethod`. The instinct to forbid `new` alone only closes the greppable path and leaves the wider hole open. The real fix is to make the type's invariant hold across **every** construction path, and to do it now while the only call sites are in-crate tests/docs (migration is trivial today; once these types are adopted across cloud-agent adapters and bindings, removing the infallible constructors becomes a breaking change).

## What Changes

- **BREAKING** Replace the `#[newtype(parse = <path>, err = <type>)]` attribute with `#[newtype(validate_fn = <path>, validate_err = <type>)]`. The validation function is invoked by the macro as `<path>(&inner)` where `inner: Inner` — it reasons about the inner type (a `String`, a `u8`, a `Vec<u8>`), not a serialization artifact. The function's first parameter may be `&Inner` or any type `&Inner` derefs to (e.g. `&str` for `String`, `&[u8]` for `Vec<u8>`, `&u8` for numeric), letting each validator pick its idiomatic borrowed form (e.g. `&str` rather than `&String`, which would trip `clippy::ptr_arg`; the macro cannot resolve types anyway, so it places no constraint beyond what the call `<path>(&inner)` type-checks against). `validate_fn` and `validate_err` are required together; `validate_err` must match `validate_fn`'s return type.
- **BREAKING** For `validate_fn`-configured types, remove the infallible `new(inner)` constructor and the quiet infallible `From<Inner>`/`From<&str>`/`From<&[u8]>` conversions. These fired implicitly via `into()`/`?`/coercion and were the insidious bypasses.
- Add a fallible `TryFrom<Inner>` (validating, move semantics) for `validate_fn`-configured types — the direct replacement steering `s.into()` callers to `s.try_into()?`. No `TryFrom<&str>`/`TryFrom<&[u8]>` (the borrowed validated path is covered by `FromStr` for string, and numeric/bytes have no borrowed string path).
- Add a uniform inherent `try_new(inner: Inner) -> Result<Self, Err>` for **every** category when `validate_fn` is configured. It validates `&Inner` directly and delegates to `TryFrom<Inner>` (one calls the other). This is the discoverable, greppable primary constructor; it also means numeric no longer needs a `u8 -> str -> u8` round-trip (the old `validate(&str)` signature forced it).
- Add a `new_unchecked(inner) -> Self` escape hatch that constructs `Self(inner)` **without** validation. It is **always `pub(crate)`** (no attribute controls it) so the invariant is enforced at the crate boundary and only the defining crate can bypass. There is no `From`-shaped hatch and no opt-in widening — a single named, greppable constructor with fixed visibility. If a future type needs cross-crate trusted construction, the derive cannot provide it; it would be hand-written.
- **BREAKING** `parse(&str)`/`FromStr` is now generated **only for the string category** when `validate_fn` is configured (string's inner IS a string; `&str → String::to_owned()` is lossless). It is **dropped for numeric and bytes**: numeric's primary entry is `try_new(u8)`/`TryFrom<u8>` (a caller with a string does `"5".parse::<u8>()?` then `Version::try_new(n)?` — two explicit steps, two distinct error types), and bytes' hex/base64url string path was always awkward and coupled to the display encoding (serde covers the wire format; explicit construction is `try_from(Vec<u8>)`).
- **BREAKING** When `validate_fn` is configured, generated `Deserialize` validates:
  - **string/numeric:** deserialize the inner value, then call `validate_fn(&inner)`; on `Err`, return `D::Error::custom(<validate_err>)`.
  - **bytes:** decode the hex/base64url string → on decode `Err`, return `D::Error::custom(<decode-err>)`; on `Ok(bytes)`, call `validate_fn(&bytes)` → on `Err`, return `D::Error::custom(<validate_err>)`. The old `expect("validation function must guarantee the string decodes in the display encoding")` contract is **deleted** — decode failure is now a first-class error, not a panic.
- Unchanged: non-`validate_fn` types (`Multihash`, bytes without a validator) keep infallible `new`, `From<Inner>`, and transparent serde — forbidding construction when no validator exists would make the type unconstructable.
- Update dogfood types' validators, docs, and tests to the new contract: `validate_did_method`/`validate_url` keep signature `fn(&str)` (the idiomatic borrowed form; `&String` would trip `clippy::ptr_arg`, and the macro's `<path>(&inner)` call deref-coerces `&String → &str`); `validate_version` changes `fn(&str)` → `fn(&u8)` and drops its internal `s.parse::<u8>()`; attributes migrate `parse = …, err = …` → `validate_fn = …, validate_err = …`; the existing `version_infallible_new_does_not_validate` test (which asserts `Version::new(0)` succeeds despite the non-zero rule) becomes a bug this change fixes, not a feature to preserve.

### Modified Capabilities
- `domain-newtype-macro`: the "Three inner categories" and "Generated constructors" requirements are revised — infallible `new` and `From<Inner>` are no longer unconditionally available; for `validate_fn`-configured types they are replaced by `TryFrom<Inner>`, a uniform `try_new(Inner)`, and a `pub(crate)` `new_unchecked` hatch; `parse`/`FromStr` is retained only for the string category; `Deserialize` is made to validate; the `parse = <path>, err = <type>` attribute is replaced by `validate_fn = <path>, validate_err = <type>` with the validation function invoked as `<path>(&inner)` (parameter `&Inner` or any type `&Inner` derefs to — e.g. `&str` for `String`, `&[u8]` for `Vec<u8>`, `&u8` for numeric).

## Impact

- **Code:** `crates/derive/src/{str,bytes,num}.rs` (macro expansion), `crates/derive/src/attr.rs` (attribute parsing — drop `parse`/`err`/`hatch`, add `validate_fn`/`validate_err`), `crates/did/src/{method,version,multihash}.rs` and `crates/core/src/url.rs` (dogfood types' validators, attributes, docs/tests).
- **APIs:** Breaking removal of `Newtype::new`, `From<Inner>` for `validate_fn`-configured types (`DidMethod`, `Url`, `Version`); breaking rename `#[newtype(parse=…, err=…)]` → `#[newtype(validate_fn=…, validate_err=…)]`; relaxing the validator signature contract from a mandated `fn(&str)` to “callable as `<path>(&inner)`” (`&Inner` or any type `&Inner` derefs to); breaking removal of `FromStr`/`parse` for numeric and bytes; new `TryFrom<Inner>`, uniform `try_new(Inner)`, `new_unchecked` (`pub(crate)`); validating `Deserialize`. `ErrorCode`/`CapabilityId` are hand-written `&'static str` newtypes, not `#[derive(Newtype)]`, and are unaffected.
- **Dependencies:** None added.
- **Migration:** All current call sites of the removed constructors are in-crate tests and doc examples (verified by repo-wide grep); no production call sites exist. Migration is mechanical. The validator signature change is also in-crate (the three `validate_*` functions are private to their modules).

# Cryptography foundation completion evidence

## Decision and evidence boundary

Issue [#286](https://github.com/hyperledger-identus/sdk-rust/issues/286)
records the following decision:

> **IDR-004 is delivered as a functional, chain-neutral cryptography and JOSE
> foundation.**

This is an evidence-bounded component decision, not a release or adoption
claim. The implementation audited here is
[`sdk-rust@fb2cc64ebe09dc382de9d903a6136f7aa8132c47`](https://github.com/hyperledger-identus/sdk-rust/tree/fb2cc64ebe09dc382de9d903a6136f7aa8132c47).
Unless a row names another revision, every repository-relative implementation
path below is evaluated at that revision. Remote issue and pull-request states
below are the 2026-09-17 snapshot recorded by issue #286 research, not a claim
about later live state.

The executable [Apollo parity manifest](apollo-crypto-parity.toml) is reused
unchanged as the frozen M2 comparison. It binds Apollo
[`ccee22bcd693e618b9b8ff3e15ed6f9c9156c27c`](https://github.com/hyperledger-identus/apollo/tree/ccee22bcd693e618b9b8ff3e15ed6f9c9156c27c)
to the SDK comparison baseline
[`9ff2fa87337d3f25d67f38486c3a4d0a656bd9d6`](https://github.com/hyperledger-identus/sdk-rust/tree/9ff2fa87337d3f25d67f38486c3a4d0a656bd9d6).
Its executable summary is 27 capabilities: 14 `parity`, 6 `sdk-exceeds`, 7
`accepted-difference`, and **0 `gap`**, with 22 mapped evidence suites. Later
JOSE, hardening, target, coverage, performance, and candidate receipts are
listed separately rather than rewriting that frozen baseline.

## Open hardening retained outside functional delivery

- [Issue #298](https://github.com/hyperledger-identus/sdk-rust/issues/298)
  owns the validated crypto-codec construction migration implemented and
  evidenced by ADR 0129 and `codec_boundaries.rs`. Its landing state is tracked
  by the issue; the former unbounded inventory row is no longer a retained SDK
  limitation in this change.
- [Issue #299](https://github.com/hyperledger-identus/sdk-rust/issues/299)
  owns the opaque validated migration for JOSE retained-input enum payloads.
  ADR 0130, the exact/one-over and compile-fail evidence, and the converted
  `jose-direct-retained-enum-construction` inventory row record its completed
  SDK-side result.

These are explicit non-functional resource-boundary hardening items. They do
not alter the implemented functional capability or claim that allocation
before the typed SDK boundary is controlled.

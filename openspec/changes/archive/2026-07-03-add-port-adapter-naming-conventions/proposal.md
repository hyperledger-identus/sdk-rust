## Why

The workspace is hexagonal (ports & adapters), but the port/adapter *type-naming* convention is unwritten: today `identus-crypto` defines the `SecureRandom` port with no suffix (good), yet its adapters `RingSystemRandom` and `DeterministicRandom` in `identus-adapters-entropy` also carry no suffix, so a reader can't tell a port from an adapter at the call site and there's no rule stopping the names from drifting toward the Java-style `*Port`/`*Adapter` mismatch. As `storage`, `transport`, and `resolver` port families land, the convention needs to be codified and *enforced* before the inconsistency multiplies. At the same time, enforcing it requires a second guard in `identus-conformance`, and the crate is currently one ~470-line `lib.rs` holding both the rulebook data and the dep-graph guard — it needs structure imposed before a second guard lands, or it becomes a mudball.

## What Changes

- Establish the port/adapter **naming convention** for the Identus Rust SDK: port traits are bare capability nouns with **no `Port` suffix** (`SecureRandom`, `Storage`, `Transport`, `Resolver`); adapter structs use the **`*Adapter` suffix** in the form `<Backend><Capability>Adapter` (e.g. `RingSystemRandomAdapter`). A `Port` suffix on port traits is explicitly **forbidden**.
- Introduce an inert **`#[identus::port]` attribute** in `identus-derive` (the existing workspace proc-macro crate). Port traits are annotated with `#[identus::port]` (e.g. `#[identus::port] pub trait SecureRandom`), which makes port-ness self-documenting at the definition site and lets the conformance guard **derive** the port set from source rather than maintaining a registry. The attribute is attached to the trait *item* (not a `Self:` bound), so it does **not** propagate to implementers — deliberately rejecting an earlier marker-supertrait design where `trait SecureRandom: Port` forced every adapter to also `impl Port` (a Rust supertrait bound is an implicit `Self:` bound), which would have added vacuous boilerplate to each adapter and collapsed the marker's meaning to "a port, or anything that implements a port."
- Enforce the **port-side** naming rule at **compile time**: the `#[identus::port]` proc-macro reads the trait name and emits `compile_error!` if it ends in `Port`, so a mis-named port fails the next `cargo build` in any crate, not only the conformance test run.
- Add a **`syn`-based naming guard** in `identus-conformance` (test-time, `#[cfg(test)]`) that (a) discovers the port set by reading `#[identus::port]` off `syn::ItemTrait.attrs`; and (b) scans `identus-adapters-*/src/` for `impl <Port> for <Struct>` and asserts `<Struct>` ends in `Adapter`. The **adapter-side** rule is enforced at test time only — it cannot be compile time without per-adapter opt-in annotation, because the type system cannot see type names on stable Rust and no macro is attached to a plain `impl` "by virtue of being an adapter." Detection uses `syn` (already a workspace dependency via `identus-derive`); because the attribute is an unambiguous token on the item, the `where`-clause-vs-supertrait disambiguation that motivated `syn`-over-regex disappears. `rust-analyzer`/LSP was considered and rejected (right idea, wrong tool: heavy, non-hermetic, unstable library API, not queryable via LSP for attribute membership).
- **BREAKING** retrofit rename of the two existing public adapters: `RingSystemRandom` → `RingSystemRandomAdapter`, `DeterministicRandom` → `DeterministicRandomAdapter` in `identus-adapters-entropy`; the deferred wasm adapter, when it lands, will be `GetrandomSystemRandomAdapter`. Version is `0.0.0`, so the break is free.
- Impose a **module structure** on `identus-conformance`: split the single `lib.rs` into a thin root, a `rulebook.rs` (the static invariant data — `Layer`/`Member`/`LayerRule`/`LAYER_RULES`, `pub(crate)`, runtime-available), and a `guard/` directory with `mod.rs` (shared helpers: file walking, manifest parsing, `syn` parsing), `dep_graph.rs` (the existing layer/dep-direction guard, moved verbatim), and `naming.rs` (the new naming guard). One module per guard; shared helpers centralized; rulebook (data) separated from guards (logic); `lib.rs` stays thin.

## Capabilities

### New Capabilities

- `naming-conventions`: the port/adapter type-naming convention for the Identus Rust SDK — port traits are bare capability nouns with no `Port` suffix (and a `Port` suffix is forbidden); the `#[identus::port]` attribute in `identus-derive` declares port-ness and enforces the no-`Port`-suffix rule at compile time; adapter structs use the `<Backend><Capability>Adapter` form and live in `identus-adapters-<family>` crates; the `syn`-based naming guard in `identus-conformance` derives the port set from the attribute and enforces the adapter suffix rule at test time.
- `conformance-crate-structure`: the internal module structure of `identus-conformance` — rulebook (data) vs guards (logic) separation, one module per guard, shared helpers in `guard/mod.rs`, rulebook `pub(crate)` + runtime-available while guards are `#[cfg(test)]`, and a thin `lib.rs` root; future guards follow the pattern without restructuring.

### Modified Capabilities

- `crypto`: the "Layer conformance — depends only on identus-core" requirement is renamed to "Layer conformance — depends only on identus-core and the proc-macro attribute provider" and its body and first scenario are updated to permit `identus-derive` (the proc-macro attribute provider) as a second allowed workspace-internal dependency alongside `identus-core`, closing the allowlist at exactly those two. The allowance is canonicalized in the new `naming-conventions` requirement "Port-owning crates depend on the proc-macro attribute provider", which the renamed `crypto` requirement cites rather than restating. The dep-graph guard's required behavior is unchanged (proc-macro crates are already exempt from the inward-direction policy, so the `identus-crypto → identus-derive` edge is layer-legal); `crate-ring-layout`'s layer/dep-direction requirements are untouched; `identus-core` gains no new trait or dependency (no `Port` marker is added).

## Impact

- **`crates/derive/src/`**: gains the inert `#[identus::port]` attribute (`#[proc_macro_attribute]`) — parses the input as `syn::ItemTrait`, emits `compile_error!` if the trait name ends in `Port`, otherwise emits the trait unchanged. No runtime semantics; no new dependency for `identus-derive` (it already uses `syn`).
- **`crates/crypto/src/securerandom.rs`**: `SecureRandom` gains the `#[identus::port]` attribute; behavior unchanged.
- **`crates/crypto/Cargo.toml`**: gains `identus-derive.workspace = true` under `[dependencies]` — a new, layer-legal (proc-macro exemption per `crate-ring-layout`), build-time-only edge; `identus-crypto` did not previously depend on `identus-derive`.
- **`crates/adapters-entropy/src/lib.rs`**: **BREAKING** rename `RingSystemRandom` → `RingSystemRandomAdapter`, `DeterministicRandom` → `DeterministicRandomAdapter` (both the struct names and their `impl SecureRandom for …` blocks); module doc-comment updated to reflect the convention.
- **`crates/conformance/src/`**: restructured — `lib.rs` becomes thin (docs, `COMPONENT`, `mod` declarations, re-exports); new `rulebook.rs` holds `Layer`/`Member`/`LayerRule`/`LAYER_RULES` (moved from `lib.rs`, `pub(crate)`); new `guard/mod.rs` holds shared helpers (file walking, root-manifest parsing, `syn` parsing) plus the `syn` dependency; `guard/dep_graph.rs` holds the existing dep-graph guard (moved verbatim from `lib.rs`'s `mod guard`); `guard/naming.rs` holds the new naming guard. `Cargo.toml` gains `syn` as a **dev-dependency** (test-only; already pinned at workspace level via `identus-derive`).
- **`crates/conformance/Cargo.toml`**: `[dev-dependencies] syn.workspace = true`.
- **Tests**: the compile-time attribute check fails a synthetic `#[identus::port] pub trait StoragePort`; the naming guard asserts (a) `SecureRandom` is discovered via `#[identus::port]` (and its name lacks the `Port` suffix), (b) `RingSystemRandomAdapter`/`DeterministicRandomAdapter` implement `SecureRandom` and end in `Adapter`, (c) a negative case where a synthetic `impl SecureRandom for BadName` is rejected; the existing dep-graph guard continues to pass unchanged after the move.
- **Assumes prior changes landed**: `crate-ring-layout` (the guard and `LAYER_RULES`), `add-crypto-capability` (the `SecureRandom` port and the two existing adapters being renamed), `workspace-dependency-conventions` (`syn` declared at workspace level, referenced via `.workspace = true`).
- **No change to the layer rules**: no `LAYER_RULES` membership or `allowed_target_layers` change; no crate is added, removed, or reparented. The new `identus-crypto → identus-derive` edge is layer-legal because proc-macro crates are already exempt from the inward-direction policy; no `Port` marker is added to `identus-core`.

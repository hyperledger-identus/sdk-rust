## Ownership and provenance findings

The JWK, COSE Key, thumbprint, and conversion implementations already belong
to generic `identus-crypto`; their representation assurance therefore belongs
in sdk-rust. NeoPRISM supplies a smaller JWK precedent, Apollo cross-language
behavior, and the three Rust consumers supply shapes, but none has a reusable
sanitizer harness to port. Original minimal seeds avoid license or provenance
ambiguity. Consumer repositories remain immutable.

The RFCs are stable immutable authorities. The repository-pinned compiler,
Nixpkgs cargo-fuzz, exact runtime binding, and existing license exception avoid
ambient installation and supply-chain drift. No standards interpretation or
new algorithm is introduced.

## Security and resource findings

Arbitrary bytes are appropriate for both public untrusted boundaries. JWK
bytes should reach serde directly so non-UTF-8, duplicate, private, extension,
and coordinate paths remain realistic. COSE bytes should remain raw except for
the documented committed-seed `hex:` transport, which is a harness convenience
and does not affect unprefixed generated bytes.

Accepted-value assertions must use public accessors and public conversion
traits. Structural equality—not format-specific extension equivalence—is the
honest JWK/COSE conversion contract. Compressed EC2 must exercise its explicit
failure path rather than decompression. An 8 KiB generator crosses COSE's 4 KiB
public ceiling while remaining bounded; five seconds and 1 GiB contain harness
or sanitizer pathology. JWK's campaign ceiling is not represented as a public
API limit.

The targets do not ingest secret keys. Custom assertion messages must not
include corpus bytes, JSON/CBOR values, coordinates, or extension names.
Failure artifacts can still contain hostile or accidentally sensitive bytes,
so retention and handling remain failure-only and untrusted.

## Automation and compatibility findings

Separate crypto and DID wrappers keep component source changes focused and
scheduled two-target soak jobs below their timeout. Reusing one independent
workspace avoids a second runtime/license/lock policy. Renaming only its
private package metadata has no consumer impact. The existing DID replay and
smoke commands must be verified as a regression gate.

No production source, public API, wire format, feature, MSRV, root lock,
target, chain behavior, consumer, release, publication, repository setting, or
`main` change is justified. Any fuzz-discovered production defect receives an
explicit compatible fix and deterministic regression or a follow-up issue; it
cannot be hidden by weakening the harness.

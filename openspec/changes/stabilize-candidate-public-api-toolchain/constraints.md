# Constraints and limitations

Impact class: material
Decision status: directed
Decision reference: https://github.com/hyperledger-identus/sdk-rust/issues/276
Constraint blockers: none

## Existing entries affected

- `SDK-RUST-001`: primary Rust remains exactly 1.98.1.
- `SDK-COMPAT-005`: nightly remains restricted to named sanitizer tooling; the
  candidate must not consume or imply a nightly compatibility provider.
- `SDK-SUPPLY-001`: Cargo, rustdoc and `cargo-public-api` stay Nix/lock owned;
  no `rustup install`, floating channel or unpinned download is permitted.
- `SDK-LIM-004`: candidate evidence remains slow weekly/manual evidence and
  does not become a required PR lane.

## Introduced or changed constraints

Rustdoc JSON SHALL be generated by the primary Nix-provided Cargo/rustdoc. The
`RUSTC_BOOTSTRAP=1` escape hatch SHALL exist only in the environment of that
single inspection command. `cargo-public-api` SHALL consume a completed local
JSON file and SHALL NOT own compiler execution or JSON generation. Missing or ambiguous JSON
output SHALL fail before API comparison or receipt publication.

## Introduced or changed limitations

Rustdoc JSON and `RUSTC_BOOTSTRAP` are unstable tooling interfaces. The evidence
is therefore reproducible only for the locked Rust 1.98.1 and parser 0.52.0
combination, and it is not proof that SDK source may use unstable Rust. The
manual repair canary still does not satisfy issue #276's first naturally
scheduled-run acceptance criterion.

## Consumer and product impact

The repair adds no network, secret, write-token, unsafe/native dependency or
runtime code. Candidate sources and API contents are unchanged. Rust, target,
wire and consumer support claims remain unchanged.

## Activation and rollback

Activation occurs only when the repair merges through protected `develop` and
the exact merged head passes a complete manual slow canary. Rollback is a
repository revert with no release cleanup; issue #276 remains open and the
candidate lane is reported as known-red.

## Evidence

The focused mutation suite, end-to-end candidate run without rustup nightly,
full factory validation, protected PR checks and post-merge slow canary are the
required evidence. The first natural scheduled run remains separate acceptance
evidence and cannot be manufactured by the manual canary.

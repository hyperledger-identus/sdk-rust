## Why

The workspace's domain-primitive layer is about to fill with typed wrappers over `String`, `Vec<u8>`, and numeric scalars — `Url`, `DidMethod`, `Multihash`, `Did`, port/version numbers, and many more. Today every one of these is hand-written with the same recurring boilerplate: a one-field struct, a `new`/`parse` constructor, an `as_str`/`as_bytes`/`get` accessor, `AsRef`/`From` conversions, `Display`, `FromStr` (with a validation predicate), `Debug`/`Clone`/`Eq`/`Hash`, and optional `serde`. The existing crates already show the pattern repeated by hand: `identus-core`'s `CapabilityId`/`ErrorCode` (`&'static str`), and neoprism's `Uri`, `PublicKeyId`, `ServiceId`, `ServiceTypeValue` (owned `String`), and `DidSuffix` (`Vec<u8>`). With `add-crypto-capability` and the upcoming `did` content landing, that boilerplate is about to multiply across every domain crate. This change introduces a single `#[derive(Newtype)]` proc-macro that packages the pattern — branching on whether the inner type is string / numeric / bytes and implementing exactly the standard traits that make sense for that category — so domain types become a few lines of declarative attribute instead of ~80 lines of mechanical impl blocks, and so the pattern stays consistent across crates.

## What Changes

- Add a new foundation-layer proc-macro crate `identus-derive` exposing a single `#[derive(Newtype)]` derive macro with `#[newtype(...)]` helper attributes. The derive inspects the single unnamed field's type and dispatches to one of three categories — **string** (`String` in v1; `Box<str>`/`&'static str` deferred), **bytes** (`Vec<u8>` in v1; `&[u8]`/`[u8; N]` deferred), **numeric** (the integer/float primitives) — generating the category-appropriate constructors, accessors, conversions, and `Display`. The broader `Box<str>`/`&'static str` and `&[u8]`/`[u8; N]` inner types are recognised as planned follow-on scope (see `design.md` Open Questions), not v1 deliverables.
- Support opt-in standard trait generation via attributes: `display` (pass-through for str/num, hex or base64url for bytes — selectable), `serde` (transparent over the inner type), and the always-on `Debug`/`Clone`/`PartialEq`/`Eq`/`Hash` are left to ordinary `#[derive(...)]` on the struct (the macro composes with standard derives rather than fighting them).
- Support fallible construction: `#[newtype(parse = <fn>, err = <type>)]` wires `FromStr` (and a `parse()` inherent method) to a caller-supplied validation function returning `Result<(), Err>`. Domain-specific error bridging (`to_identus_error()`) stays hand-written by the owning crate — the macro generates generic boilerplate only, matching the `core-error-conventions` two-surface split.
- Land the first adoptions: `Url` in `identus-core` (shared by `did`/`openid4vc`/`trust`, which depend inward on foundation) and `DidMethod` + `Multihash` in `identus-did`. These dogfood all three categories (str, bytes, and one numeric example). `Multihash` is the canonical method-agnostic bytes identifier underlying `did:key` (and the wider multihash/multibase ecosystem); it fills the bytes-category slot previously held by the PRISM-specific `DidSuffix` without tying the dogfood to a `did:prism`-only type.
- Carve proc-macro crates out of the inward-direction layer rules: any crate MAY depend on `identus-derive` regardless of layer, because it is a build-time proc-macro and not a runtime domain dependency. The `crate-ring-layout` `LAYER_RULES` membership table and the dep-graph guard are updated to (a) add `identus-derive` as a foundation member marked `proc_macro = true`, and (b) exempt `proc_macro = true` crates from the inward-direction check. This is what makes `identus-core` (foundation, "no workspace deps") able to use `#[derive(Newtype)]` for `Url` without violating the layer rule.

## Capabilities

### New Capabilities

- `domain-newtype-macro`: the `#[derive(Newtype)]` proc-macro and its `#[newtype(...)]` attribute contract — category dispatch (string/numeric/bytes), generated constructors/accessors/conversions, opt-in `display`/`serde`, fallible `parse` with a caller-supplied validation function and error type, and the rule that domain-specific error bridging is hand-written on top.

### Modified Capabilities

- `crate-ring-layout`: the `LAYER_RULES` const gains `identus-derive` as a foundation-layer member flagged `proc_macro = true`, and the dep-graph guard exempts `proc_macro = true` workspace crates from the inward-direction policy so any crate (including the otherwise-dependency-free `identus-core`) may depend on a proc-macro crate. This is required because `Url` lives in `identus-core` and is built with the derive; without the carve-out, `identus-core` → `identus-derive` would violate `foundation → none`.
- `core-error-conventions`: the "Foundation crate has no workspace dependencies" requirement is MODIFIED to carve out build-time proc-macro dependencies, mirroring the `crate-ring-layout` carve-out: `identus-core` SHALL declare no `identus-*` *runtime* dependencies, and a build-time dependency on a workspace crate whose `Cargo.toml` declares `[lib] proc-macro = true` (e.g. `identus-derive`) is permitted. This is required because `Url` lives in `identus-core` and is built with `#[derive(Newtype)]`, so `identus-core` gains `identus-derive` as a build-time dependency; without the carve-out, the existing `core-error-conventions` invariant forbidding any `identus-*` workspace dependency would be violated. The macro remains the recommended way to wire `FromStr` on new domain newtypes, and the owning crate still hand-writes `to_identus_error()` for the resulting `FromStr::Err`. `Url`'s rich local error and its `to_identus_error()` mapping follow the existing two-surface pattern as the first `identus-core` resident that has a fallible parse. Additionally, the `core-error-conventions` "Component metadata" requirement is MODIFIED to exempt crates whose `Cargo.toml` declares `[lib] proc-macro = true` (e.g. `identus-derive`): such build-time proc-macro crates are not runtime crates and cannot export non-macro items to downstream crates, so they SHALL NOT be required to expose `pub const COMPONENT`. This keeps `identus-derive` from needing a runtime dependency on `identus-core` (which would itself violate `foundation → none`) merely to satisfy the component-metadata obligation.

This change **intentionally collides** with `add-adapter-crate-layer` on two shared `crate-ring-layout` requirement headers: `Crate stubs at minimal code depth` (which `add-adapter-crate-layer` renames from `Twelve crate stubs at minimal code depth` and reframes to a non-literal, adapter-family-tolerant body) and `Workspace dependency map` (which `add-adapter-crate-layer` rewrites to a `LAYER_RULES`-derived count). This change MODIFIES the same two (post-rename) headers to add the `identus-derive` exclusion (stub set) and the `proc_macro` carve-out / derived count (guard + dep map). Resolution is by archive ordering: **`add-adapter-crate-layer` archives first** (its RENAMED + MODIFIED blocks are self-contained and carry no `identus-derive` content), then this change archives second with its MODIFIED blocks retargeted to the renamed header `Crate stubs at minimal code depth` and carrying the full combined content (founding runtime stubs + `identus-adapters-entropy` + by-reference admission + `identus-derive` exclusion; derived workspace-dep set including both `identus-adapters-entropy` and `identus-derive`). Because the retargeted MODIFIED header does not exist in the current main spec until `add-adapter-crate-layer` archives, this change is **archive-blocked-by `add-adapter-crate-layer`** and not standalone-archivable before then (`openspec validate` still passes structurally; the header-existence check is enforced at archive time by `buildUpdatedSpec`).

## Impact

- **New crate `crates/derive/`** (`identus-derive`, `proc-macro = true`): `src/lib.rs` exposes `#[derive(Newtype)]`; implementation modules per category (`str`, `bytes`, `num`) plus attribute parsing; `src/lib.rs` exposes only the derive (no `pub const COMPONENT` — proc-macro crates are exempt from the `core-error-conventions` "Component metadata" obligation). External deps `syn` 2, `quote` 1, `proc-macro2` 1, declared in root `[workspace.dependencies]` and referenced via `.workspace = true` per `workspace-dependency-conventions`.
- **`crates/core/`**: gains `identus-derive` (workspace, proc-macro — exempt from the layer guard by the carve-out, and exempt from the `core-error-conventions` "Foundation crate has no workspace dependencies" requirement by the parallel MODIFIED carve-out) and a new `Url` newtype module (`src/url.rs`) built with `#[derive(Newtype)]`, including a `UrlError` rich local error + `to_identus_error()` mapping to a stable `ErrorCode` (e.g. `core.invalid_url`). `Url` validation backend is a design decision (hand-rolled scheme/authority/path check vs the `url` crate); if an external crate is pulled in, `identus-core` gains its first external dep, called out explicitly in `design.md`.
- **`crates/did/`**: gains `identus-derive` and new `DidMethod` (string, validated) and `Multihash` (bytes) newtypes built with the derive, with hand-written `to_identus_error()` bridging for each `FromStr::Err`.
- **`crates/conformance/src/lib.rs`**: the `LAYER_RULES` const gains the `proc_macro` flag on members and an `identus-derive` foundation entry; the guard test adds a proc-macro exemption branch and a scenario asserting `identus-core → identus-derive` is permitted while `identus-core → identus-did` is still rejected.
- **Root `Cargo.toml`**: `[workspace.dependencies]` gains `identus-derive = { path = "crates/derive" }` plus `syn`/`quote`/`proc-macro2` (and `url`/`uriparse` only if the chosen `Url` validation backend requires one).
- **Tests**: macro unit tests (proc-macro expansion via `trybuild` for compile-fail + positive snapshots), per-category expansion tests, and adoption tests (`Url`/`DidMethod`/`Multihash` round-trips, invalid-input rejection, error-bridging mapping to stable `IdentusError` codes with redaction-safe `Display`).
- **Assumes prior changes landed**: `crate-ring-layout` (the guard and `LAYER_RULES`), `workspace-dependency-conventions` (external deps declared at workspace level), and `core-error-conventions` (the two-surface bridging the adoptions follow).
- **No change to `identus-core`'s existing `CapabilityId`/`ErrorCode`**: those are `&'static str` `const fn` newtypes that the proc-macro cannot emit (`const fn` generation is out of scope); they stay hand-written. The macro targets owned-`String`/`Vec<u8>`/numeric newtypes.
